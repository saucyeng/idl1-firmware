# PORT-CHECKLIST — IDL1 pod sensors: LSM6DSV320X + ATS601LSG + analog input

Run `2026-08-31-pod-delta` · read-only synthesis · no firmware written. Owner scope note (2026-08-31 21:20): the pressure transducer is undecided — the analog channel is prepared as a generic single-ended input.

## How to use this

Every row is sized **transcription** (the change is fully specified by a cited row in this run's findings — dispatch to a cheap model) or **judgment** (a design choice remains — mid tier or a human). Rows marked **PROVISIONAL — Qn** were built on the recommended answer in `questions.md`; answer the blank there and the row stands or changes.

Facts behind the rows, in order of authority:
1. `regs-bitmap.md` — verbatim DSV320X register bit rows with `lsm6dsv320x.md` line cites (DSO32 columns unreliable; use `components/lsm6dso32x_STdC/lsm6dso32x_reg.h` for the old part).
2. `regs-identity-boot.md`, `regs-ctrl.md`, `regs-fifo.md`, `regs-interrupts.md`, `regs-spi.md`, `regs-i2c.md`, `regs-selftest.md` — the DSO32→DSV320X delta, page-cited. **Their bit *positions* are not to be trusted** (three miscounts found and annotated at the bottom of the affected files); addresses, defaults, encodings and values are.
3. `driver-impact.md` — every `file:line` in the IDL0 IMU path that breaks, the STdC swap verdict, the duplication map.
4. `new-sensors.md` + `tla2528-regmap.md` — ATS601, signal paths, TLA2528 registers/opcodes/timing (the register-sequence table inside `new-sensors.md` is superseded by `tla2528-regmap.md`).
5. Board wiring: `idl1-hardware/docs/datasheet/breakout/data/board-facts.md` (pod) and `idl1-hardware/docs/datasheet/idl1/data/board-facts.md` (main board) — netlist-derived.

Verified wiring the whole list rests on: the pod's LSM6DSV320X is on **I2C** (CS tied to VDDIO, INT1/INT2 unconnected, address LSB by JP1/R1); IDL1's onboard IMU is **also** an LSM6DSV320X on SPI (CS GPIO21, bus shared with microSD); the DSO32 does not exist on IDL1. ATS601 OUT → XIAO **GPIO0** (front) / **GPIO1** (rear) with 4k7 pull-up + 10 nF + 330 R on the main board. Pod analog → **TLA2528** AIN5 (front) / AIN4 (rear), I2C 0x17, same bus as the pod IMUs. `PWR_EN` = GPIO2 gates the switched +3V3 that feeds all of it. The ESP32-C6 I2C controller supports **100 / 400 kbit/s only** (datasheet §4.2.1.3).

Recommended execution order: **A2 → A7 → (A1, A3, A4, A5, A6, A8, A12, A13, A14) → A9, A10, A11 → D1–D3 → B → C**. A7 (dedupe) first means every later IMU edit is made once, not twice.

Item count: A-code 15 · B 7 · C 8 · D 4 = 34 work items, of which **21 pure transcription, 7 pure judgment, 4 mixed** (a transcription carrying one embedded choice), 2 no-op/logged; 8 rows are PROVISIONAL on a question. A-reg: 30 register mappings (22 transcription values, 8 informational). Questions: 7.
